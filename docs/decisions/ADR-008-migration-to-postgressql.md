### ADR-008: Migration to PostgreSQL for Session Persistence

**Context:** The current architecture relies on `mandarin_session.json` for state management. This ephemeral local file system approach prohibits horizontal scaling, risks data corruption under concurrent load, and violates stateless container paradigms required for cloud deployment. **Decision:** Adopt PostgreSQL (via Supabase) as the persistent data store. We will utilize `asyncpg` directly for database interactions to bypass ORM overhead (like SQLAlchemy) and maximize throughput for latency-sensitive chat streaming endpoints. **Consequences:** Introduces an external infrastructure dependency (Supabase). Requires schema migrations. `asyncpg` connection pooling must be tightly bound to the FastAPI ASGI lifecycle to prevent connection leaks during worker reloads.
